# Рецепты API-фиксов

Каждый фикс описан с точки зрения: что находим, что записываем, какой `--fix` использовать в `apply_fixes.py`.

## 1. countdown — Истёкшие акции

**Триггер:** `countdown_end_time < now()` И `countdown_description` не пустой

**Что пишем:** `countdown_end_time = ""` (пустая строка обнуляет таймер). Опционально — также очищаем `countdown_description`.

**Запуск:**
```bash
python3 apply_fixes.py --fix countdown [--dry-run] [--extend-days N]
```

- Без флагов: обнуляет все истёкшие
- С `--extend-days 14`: продлевает на 14 дней от now()

**Безопасность:** идемпотентно. Не трогает таймеры в будущем.

## 2. mod-title — Заполнение названий модификаций

**Триггер:** товар где `article != parent_article` (модификация) И `mod_title.<lang>` пустой

**Что пишем:** `mod_title.<lang>` берётся из ключевой характеристики, по умолчанию `rozmr` (размер). Если несколько отличающихся характеристик в группе — собираем композит (например, `Двоспальний / Білий`).

**Алгоритм определения ключа:** для каждой группы модификаций смотрим какие характеристики **отличаются** между модификациями. Берём отличающиеся как mod_title.

```bash
python3 apply_fixes.py --fix mod-title [--dry-run]
```

**Превью:** скрипт показывает первые 10 модификаций с предложенным mod_title — пользователь подтверждает, потом импортит.

## 3. discount — Пересчёт скидки

**Триггер:** `price_old > price > 0` И `discount in (0, "0", null)`

**Что пишем:** `discount = round((price_old - price) / price_old * 100)` (целое число процентов)

```bash
python3 apply_fixes.py --fix discount [--dry-run]
```

**Безопасность:** не трогает товары где `discount` уже задан. Не пишет если `price_old == price` или `price_old == 0`.

## 4. seo — Заполнение пустых SEO-полей

**Триггер:** главные товары с пустым `seo_title`, `seo_description`, `seo_keywords` или `h1_title`

**Алгоритм генерации (без LLM, по шаблону):**

Контекст для каждого товара:
- `title` — название
- `kolr` или `color` — цвет (если есть)
- `rozmr` — размер (если есть)
- `materal` — материал (если есть)
- `brand` — бренд
- `category` — название родительской категории

Шаблоны:
```
seo_title:    "{title} — {brand} | купити з доставкою"  (≤70 симв)
seo_description: "{title} {color} з {material}. {short_desc[:100]}"  (≤160 симв)
seo_keywords: "{title нижним}, {category нижним}, {color}, купити {category}"
h1_title:     "{title}"
```

```bash
python3 apply_fixes.py --fix seo --preview-only  # показать что сгенерил
python3 apply_fixes.py --fix seo                  # записать
```

**Превью обязательно** — скрипт сначала показывает первые 5 пар (текущее → предложенное), пользователь подтверждает.

## 5. mpn — Генерация MPN

**Триггер:** главные товары с пустым `mpn`

**Что пишем:** `mpn = "<PREFIX>-<article>"`. По умолчанию `PREFIX` = первые 2-4 буквы названия бренда (например `MyBrand` → `MB`). Можно переопределить через `--prefix`.

```bash
python3 apply_fixes.py --fix mpn [--prefix PT] [--dry-run]
```

**Безопасность:** не перезаписывает существующие `mpn`. Если `gtin` тоже пуст — не трогаем (это не MPN).

## 6. dup-desc — Уникализация дублирующих описаний

**Триггер:** `description` (text) совпадает между разными `article` главных товаров

**Алгоритм:**
1. Найти группы дубликатов
2. **Получить от пользователя стратегию переписывания:**
   - 🅰 Вариативная замена (заменяем цвет/размер/название в одном тексте на свойства каждого товара)
   - 🅱 Уникальное переписывание каждого (нужны новые тексты)
3. Для 🅰 — извлекаем общий шаблон, заменяем по placeholder'ам
4. Для 🅱 — Claude генерирует новый текст для каждого товара отдельно

**Превью обязательно** — скрипт сохраняет proposed_descriptions.json, пользователь смотрит, правит, потом импорт.

```bash
python3 apply_fixes.py --fix dup-desc --strategy A [--dry-run]
python3 apply_fixes.py --fix dup-desc --strategy B  # генерация → пауза → подтверждение
```

## 7. installments — Включение оплаты частями

**Триггер:** товары с `installments_payment.id == 1` (выкл) и `monobank_installments_payment.id == 1`

**Что пишем:**
- `installments_payment.id = 2` (по умолчанию ПриватБанк, обычно 3 платежа)
- `monobank_installments_payment.id = 2`

```bash
python3 apply_fixes.py --fix installments [--dry-run]
```

**Edge case:** если в админке клиента не подключены эти услуги, `catalog/import` вернёт код 11 (поле не в шаблоне). В этом случае показываем пользователю, что нужно сначала включить функцию в админке: **Налаштування → Система → Каталог → Шаблон даних → Оплата частинами**.

## 8. sticker-sale — Стикер «Распродажа»

**Триггер:** товары с `price_old > price > 0` И в `icons[]` нет ни одного стикера со словом «распродаж» / «знижк» / «sale»

**Что пишем:** `icons` добавляется текущий список + новый стикер. Имя стикера определяется из существующего набора магазина (через `icons/export` если v4, иначе берём первый подходящий из встретившихся товаров).

**Дефолт:** "Распродажа" (так в каталоге Хорошопа). Можно переопределить через `--sticker-name "Sale"`.

```bash
python3 apply_fixes.py --fix sticker-sale [--sticker-name "Распродажа"] [--dry-run]
```

## 9. inline-styles — Очистка inline-стилей

**Триггер:** в `description` (HTML) больше 5 атрибутов `style="..."`

**Алгоритм:**
1. `re.sub(r'\s*style\s*=\s*"[^"]*"', '', html)` — убираем все inline-стили
2. **Поднимаем смысловые подзаголовки до h2:** ищем `<p[^>]*>(Догляд|Особливості|Розмір|Доставка|Склад)[^<]*</p>` → заменяем на `<h2>...</h2>`. Список ключевых подзаголовков — параметризуется.

**Перед записью:** скрипт сохраняет diff (старая → новая версия для первых 3 товаров) — пользователь смотрит результат и подтверждает.

```bash
python3 apply_fixes.py --fix inline-styles [--preview-only]
```

**Edge case:** если в HTML есть `<style>` блок (внутри описания) — оставляем нетронутым, чистим только атрибуты `style=`.

## 10. cross-sell — Привязка accessories/alt_parent

**Триггер:** main-товары с пустым `accessories` И/ИЛИ `alt_parent`

**Этот фикс ВСЕГДА требует обсуждения с пользователем:**

Вопросы:
1. Какие категории привязать как `accessories`? (например: для постели — простыни, подушки, наволочки)
2. Какие категории как `alt_parent`? (например: «Хіти продажів» для топ-N по `popularity`)
3. Включаем ли подарки (`gifts`)? Если да — какой подарок к какому товару

**Скрипт работает в режиме интерактива:**
```bash
python3 apply_fixes.py --fix cross-sell --interactive
```

Спрашивает у пользователя:
- Какую категорию аксессуаров привязать ко всем товарам в категории X
- Сколько топ-N товаров перевести в alt_parent "Хіти" (по popularity)

Без `--interactive` — скрипт пишет в stdout что нужно решить и выходит без изменений.

## 11. decode-entities — Раскодирование сырых HTML-entities

**Триггер:** main-товары, в `description` / `short_description` / `marketplace_description` которых есть необработанные HTML-сущности: `&ndash;`, `&mdash;`, `&deg;`, `&nbsp;`, `&laquo;`, `&rsquo;`, `&sup2;`, `&times;` и т.д.

**Причина:** артефакт импорта — двойное экранирование при выгрузке из CSV или старого движка. Покупатель видит буквально `Діагональ 5&deg; &ndash; 10&deg;` вместо `Діагональ 5° – 10°`.

**Чем отличается от inline-styles:** `inline-styles` чистит `style="..."` атрибуты (визуальный мусор в коде). `decode-entities` раскрывает текстовые сущности (мусор, видимый покупателю). Это разные проблемы — на боевом каталоге было ~2019 товаров с entities против ~5 с inline-стилями.

**Что делает:** `html.unescape()` по трём текстовым полям, запись через `catalog/import`.

```bash
python3 apply_fixes.py --fix decode-entities --preview-only   # посмотреть before→after
python3 apply_fixes.py --fix decode-entities                  # применить (спросит y/N)
```

**Превью обязательно** — показывает before/after на 3 товарах + общий счётчик entities. После подтверждения пишет лог `fix_decode_entities_<ts>.json`.

**Edge-case:** `&lt;` / `&gt;` / `&amp;` внутри текста, где это намеренно экранированный код в примерах (редко в e-commerce) — `unescape` их тоже раскроет. На каталогах товаров это почти всегда безопасно, но проверь превью если магазин про программирование/HTML.

## Общие принципы для всех фиксов

1. **Все фиксы поддерживают `--dry-run`** — выводят что будет сделано без записи
2. **Контентные (4, 6, 9, 10) требуют превью** — показываем 3-5 примеров до записи
3. **Batch-импорт по 50** — лимит Хорошопа
4. **Логирование:** каждый фикс пишет лог `fix_<name>_<timestamp>.json` с пред/пост состояниями (для отката если что)
5. **Идемпотентность:** повторный запуск того же фикса не должен ломать данные
6. **Обработка кода 11 от API:** если поле не в шаблоне — показываем где включить в админке

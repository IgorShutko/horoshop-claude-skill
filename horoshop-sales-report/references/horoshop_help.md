## API заказов

### `orders/get` (POST)

**URL:** `https://<DOMAIN>/api/orders/get/`

**Параметры:**
- `from`, `to` — даты в формате `YYYY-MM-DD` или `DD.MM.YYYY` (с v3.30 — с временем)
- `status` — фильтр по статусу (массив или одно значение)
- `ids[]` — конкретные order_id
- `additionalData: true` — добавляет ТТН Новой почты, склады отправителя/получателя
- `offset`, `limit` — пагинация

📄 [API заказов](https://help.horoshop.ua/ru/articles/3960898-api)

## Статусы заказов

### Стандартные ID (везде одинаковые)
| ID | Статус UA | Статус RU | `is_successful` |
|---|---|---|---|
| 1 | Нове | Новый | 0 |
| 2 | В обробці | В обработке | 0 |
| 3 | **Доставлене** | **Доставлен** | **1** ← это «успешный» заказ |
| 4 | Не доставлене | Не доставлен | 0 |
| 6 | Надіслане | Доставляется | 0 |

### Кастомные статусы (с v4.0)
- Магазин может добавлять свои статусы (например «Очікує оплати», «Скасовано клієнтом»)
- Получить полный список: `POST /api/orders/get_available_statuses` (v4)
- В каждом статусе есть `is_successful: 0|1` — определяет, считается ли заказ доставленным

### Важно для отчётов
- **Выручка считается ТОЛЬКО по статусу 3 (доставлен)** — это завершённый заказ
- Заказы в статусах 1, 2, 6 — **в pipeline** (могут стать выручкой или отвалиться)
- Заказы в статусе 4 — **не считаются**

📄 [Обработка заказов](https://help.horoshop.ua/ru/articles/1703603-обработка-заказов)

## Финансовые поля заказа

| Поле | Что значит |
|---|---|
| `total_default` | Сумма товаров без скидок |
| `total_sum` | **Итоговая сумма (с учётом скидок, БЕЗ доставки)** ← это выручка |
| `total_quantity` | Общее кол-во товаров в заказе |
| `delivery_price` | Стоимость доставки (`-1` = по тарифам перевозчика) |
| `payment_price` | Комиссия за оплату |
| `discount_value` | Сумма скидки (абсолютная) |
| `discount_percent` | % скидки |
| `coupon_discount_value` | Скидка по купону |
| `manager_discount` | Скидка менеджера |

### Расчёт средней стоимости заказа (AOV)
```
AOV = sum(total_sum) / count(orders) — для доставленных
```

### Расчёт revenue
```
revenue = sum(total_sum where stat_status == 3)
```

## UTM в заказах (analytics)

### Поля в `orders[i].analytics`
- `utm_source`
- `utm_medium`
- `utm_campaign`
- `utm_term`
- `utm_content`
- `google_client_id` — GA Client ID

### Особенности
- Если заказ оформлен через прямой заход — `utm_source: ""` или `(none)` → консолидируется как `(direct/none)`
- Шаблоны UTM (типа `{campaign_id}`) — иногда попадают в БД при неправильной настройке Google Ads
- `google_client_id` помогает связать заказ с сессией GA для аттрибуции

📄 [UTM-метки в письмах](https://help.horoshop.ua/ru/articles/4098496-utm-метки-в-триггерных-письмах-магазина)

## Доставка (типы и парсинг)

### `delivery_type.id`
| ID | Тип |
|---|---|
| 3 | Новой почтой |
| 8 | Самовывоз |
| 9 | Укрпочтой |

⚠️ **На каждом проекте ID могут отличаться** — это определяется настройкой магазина. Для точного маппинга используй `delivery/export` (если нужно — см. `04_Варианты_доставки.md`).

### Блок `delivery_data` (новый формат)
- Для Нової Пошти: `delivery_data.nova_poshta`
- Для Укрпочти: `delivery_data.ukrposhta`
- Содержит: `tnNumber`, `tnStatusName`, `estimatedDeliveryDate`, `departure`, `destination`

### Старый формат (`additional_data`)
- Используется только для Нової Пошти
- В будущем будет удалён — рекомендуется переходить на `delivery_data`

## Оплата (типы)

### `payment_type.id` (стандартные)
| ID | Тип |
|---|---|
| 13 | Готівкою / Наличными |
| 14 | Онлайн-оплата кредитною карткою |
| 15 | Оплата при отриманні (накладений платіж) |

⚠️ **На каждом проекте ID могут отличаться.**

### `payed`
- `0` — не оплачен
- `1` — оплачен

### Для отчёта — пайплайн оплат
Если магазин не закрывает заказы статусом 3, но `payed: 1` — это завершенный заказ (для отчёта можно учесть в «потенциальной выручке»).

## Товары в заказе

### `orders[i].products[j]`
| Поле | Что |
|---|---|
| `title` | Название |
| `article` | Артикул |
| `price` | Цена за единицу |
| `quantity` | Количество |
| `total_price` | Итог по позиции |
| `discount_marker` | Тип скидки: `PRICE_OLD` / `PAGE_DISCOUNT` / `DISCOUNT_CARD` / `DISCOUNT_NONE` / `NONE` |
| `type` (v4.7+) | `gift_parent` / `gift` / `set_main` / `set_item` |
| `storage_id`, `parent_storage_id` | Связь между основным и подарком/комплектом |

### Подарки и комплекты (v4.7+)
- Главный товар: `type: "gift_parent"` или `set_main`
- Подарок/деталь: `parent_storage_id` ссылается на `storage_id` главного

При расчёте ABC-анализа — обычно учитывают только основные товары (`type: null` или `gift_parent` или `set_main`), не подарки.

## ABC-анализ (Парето 80/15/5)

> Это не из справки Хорошопа, но стандартная методология.

### Группировка по выручке
- **A** — товары, дающие первые 80% выручки (обычно 5-20% SKU)
- **B** — следующие 15% выручки (15-30% SKU)
- **C** — оставшиеся 5% выручки (50-80% SKU)

### Что делать с группами
- **A** — оптимизировать карточки (фото, тексты, SEO), маркетинг, наличие
- **B** — поддерживать
- **C** — кандидаты на удаление / распродажу / архивирование

## Доступные отчёты в админке (для сравнения с нашим)

- **Маркетинг → Звіти → Продажі** — daily/weekly/monthly + по категориям
- **Маркетинг → Звіти → Покупці** — топ покупателей
- **Маркетинг → Звіти → Конверсії** — funnel: визиты → корзина → заказ

## Ограничения для отчёта

### Не возвращается через `orders/get`
- Источник трафика на товар (только через GA / Meta Pixel)
- Customer Lifetime Value (нужно построить самим из истории заказов)
- Returns / возвраты (только через статус «Не доставлен» или ручной возврат)

### Что вычисляем сами в скилле
- Динамика (день/неделя/месяц)
- ABC-анализ
- AOV
- Конверсия из pipeline (статусы 1-2-6 → 3)
- Источники по UTM (consolidated)

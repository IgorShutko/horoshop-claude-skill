# Horoshop Orders API — справочник для скилла

## `orders/get` — главный endpoint

```
POST https://<DOMAIN>/api/orders/get/
Content-Type: application/json
```

**Параметры:**
- `token` — обязательный
- `from` — `YYYY-MM-DD` или `DD.MM.YYYY` (включительно)
- `to` — то же
- `ids[]` — конкретные заказы по номерам
- `status` — int или массив. Возможные: 1, 2, 3, 4, 6 (см. ниже)
- `additionalData` — bool, доп. данные ТТН Новой Почты
- `offset`, `limit` — пагинация (используем `limit=500`, increment offset)

## Статусы заказов

| ID | Стандартное имя | Что значит для отчёта |
|----|---|---|
| 1 | Новый | потенциальная выручка |
| 2 | В обработке | потенциальная выручка |
| 3 | **Доставлен** | **реальная выручка — это считаем** |
| 4 | Не доставлен / отменён | потерянная выручка |
| 6 | Доставляется | в пути, ещё не реальная выручка |

**Кастомные статусы:** магазин может добавлять свои. Получить весь список через `orders/get_available_statuses` (доступно с v4.0).

## Ключевые поля заказа

```json
{
  "order_id": 123,
  "stat_status": 3,
  "stat_created": "2026-04-15 10:30:00",
  "total_default": 1500,        // без скидок
  "total_sum": 1200,            // с учётом скидок (что считаем как выручку)
  "total_quantity": 2,
  "discount_value": 300,
  "delivery_price": 60,         // НЕ включён в total_sum
  "currency": "UAH",
  "payment_type": {"id": 13, "title": "Наличными"},
  "delivery_type": {"id": 3, "title": "Новой почтой"},
  "products": [
    {
      "article": "ABC123",
      "title": "Товар",
      "price": 600,
      "quantity": 2,
      "total_price": 1200,
      "type": "set_main",       // или gift_parent / gift / set_item
      "discount_marker": "PRICE_OLD"
    }
  ],
  "analytics": {
    "utm_source": "google",
    "utm_medium": "cpc",
    "utm_campaign": "brand",
    "google_client_id": "GA1.x.xxx"
  }
}
```

## Что используем в скилле

- **Выручка** = сумма `total_sum` доставленных (`stat_status = 3`)
- **Средний чек** = выручка / число доставленных
- **AOV all** = средний чек по всем статусам (для сравнения)
- **ABC** = по `products[].total_price` для доставленных, group by `article`
  - Игнорируем товары с `type` in (`gift`, `set_item`) — они вторичны
- **UTM** = `analytics.utm_source` доставленных
- **Динамика** = по `stat_created` (день/неделя/месяц)

## Что НЕ считаем

- ❌ `delivery_price` к выручке — это деньги перевозчика, не магазина
- ❌ Заказы со статусами 1, 2, 6 — потенциальная, не реальная выручка
- ❌ Товары `type: gift` — у них `total_price = 0` обычно, не дают выручку

## Edge cases

- **`payed: 0` при `stat_status: 3`** — заказ доставлен, но не оплачен (например наложка не выкуплена). Технически — не выручка. Но Хорошоп ставит status=3 после доставки независимо от оплаты. Учитываем как выручку, помечаем для уточнения если % отмен после доставки большой.
- **Кастомные статусы у магазина** — если в `stat_status` приходит 5/7/8/etc. — скилл выводит их в раздел «По статусам» с пометкой «кастомный». Юзер может посмотреть имена через `orders/get_available_statuses`.
- **Заказы без UTM** (`analytics.utm_source: "(none)"` или пусто) — группируем под `(direct/none)`. Если их >50% — флажок про сломанный трекинг.

## Лимиты

- В одном ответе: до **500 заказов** (по умолчанию). Жёсткого верхнего лимита в доке нет.
- Большой период (>1000 заказов) — обязательная пагинация через `offset`/`limit`
- Token TTL: 600 сек, обновляется при необходимости

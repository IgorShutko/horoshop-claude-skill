# Horoshop Photo Audit

Глубокий аудит фотографий товаров: количество, размеры, дубликаты.

## Что проверяет

| Чек | Стандарт | Почему |
|---|---|---|
| Количество фото на товар | ≥ 4 | E-commerce стандарт. Меньше — низкая конверсия |
| Размер файла | ≤ 500 KB | Тяжёлые фото портят LCP, мобильную скорость |
| Только 1 фото | ≤ 5% товаров | Много товаров с одной фоткой — недоснятый каталог |
| Без фото | 0 | Совсем без фото — товар невидим в листинге |
| Дубли главных фото между товарами | 0 | Часто баг импорта — все товары показывают одну картинку |
| `gallery_360` | опционально | Только для high-end категорий |

## Pipeline

```
[1] Auth + выгрузка каталога
[2] Анализ images/gallery_common каждого товара
[3] HEAD-запросы на главные фото (проверка статуса + размера)
[4] Поиск дубликатов
[5] PHOTO_REPORT.md с рекомендациями что доснять
```

## Использование

```bash
mkdir -p photo_<domain>
cd photo_<domain>
HOROSHOP_DOMAIN=<DOMAIN> HOROSHOP_LOGIN=<LOGIN> HOROSHOP_PASSWORD=<PASSWORD> \
  python3 ${SKILL_DIR}/scripts/photo_audit.py
```

Опции:
- `--from-file catalog.json` — без обращения к API
- `--min-photos 4` — порог (default 4)
- `--max-size-kb 500` — макс размер фото (default 500)
- `--check-sizes` — делать HEAD-запросы (медленнее, но точнее)

## Output

- `catalog.json` — выгрузка
- `photo_audit.json` — все находки
- `PHOTO_REPORT.md` — отчёт

## Tone

Spike-стиль. Цифры. Без воды.

## Что НЕ делать

- ❌ Не заменять автоматически фото — это всегда ручная работа клиента
- ❌ Не предлагать AI-генерацию фото товаров (это другая задача — `seo-image-gen` если нужно для категорий, не товаров)
- ❌ Не качать все фото для проверки разрешения — слишком долго. Размер через HEAD достаточно.

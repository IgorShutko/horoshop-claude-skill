# Полный чек-лист аудита Хорошопа — 22 проверки

22 проверки разделены на три категории:
- **10 API-фиксов** — пакетно правятся через `apply_fixes.py`
- **8 admin-задач** — только вручную в админке
- **4 баг-проверки данных** — выводятся в отчёт, фиксить в источнике (CSV-импорт, ERP, ручная правка карточки)

Каждая проверка имеет:
- **Что:** на что смотрим
- **Почему:** какое влияние на SEO/UX/конверсии
- **Где править:** API / админка / данные

## API — 10 проверок (исправляются через `catalog/import`)

### 1. Истёкшие акции `countdown_end_time`

- **Что:** товары с датой `countdown_end_time` в прошлом, при этом `countdown_description` заполнено
- **Почему:** мёртвый таймер на странице товара = подрыв доверия, "фейковая срочность", негативный UX. Google неодобрительно относится к фейковой срочности.
- **Фикс:** `countdown` — обнуление даты или продление на N дней

### 2. Пустой `mod_title` у дочерних модификаций

- **Что:** товары где `article != parent_article` и `mod_title.<lang>` пустой, но при этом есть характеристика типа `rozmr` (размер) или `kolr` (цвет)
- **Почему:** в селекторе модификаций пользователь должен видеть осмысленное название. Пустой mod_title = плохой UX выбора варианта.
- **Фикс:** `mod-title` — заполнение из `rozmr` или другой ключевой характеристики

### 3. `discount=0` при реальной скидке

- **Что:** `price < price_old` (есть скидка), но `discount = 0`
- **Почему:** Хорошоп выводит стикер `-X%` на основе `discount`. Если 0 — стикер скрыт, теряется визуальный CTA в каталоге.
- **Фикс:** `discount` — пересчёт `discount = round((price_old - price) / price_old * 100)`

### 4. Пустые SEO-поля у товаров

- **Что:** главные товары (`article == parent_article`) с пустыми `seo_title`, `seo_description`, `seo_keywords` или `h1_title`
- **Почему:** SEO-шаблон даёт дефолт, но для отдельных товаров уникальные мета-теги дают контроль над сниппетом и CTR.
- **Фикс:** `seo` — генерация SEO по контексту (название, цвет, размер, цена). **Превью обязательно.**

### 5. Отсутствие `mpn` (и опционально `gtin`)

- **Что:** главные товары без `mpn`
- **Почему:** Google Shopping/Rozetka/Facebook фиды требуют идентификатор. Без него — отказ модерации или низкий quality score.
- **Фикс:** `mpn` — шаблон `<BRAND>-<article>` (e.g. `PT-1248`). Для собственного производства — допустимо.

### 6. Дубликаты `description`

- **Что:** одинаковый text-контент описания у разных товаров
- **Почему:** Google пенализирует дубли каноникализацией → одна страница ранжируется, другая теряется.
- **Фикс:** `dup-desc` — переписать каждый дубль уникально под характеристики (цвет/размер/коллекция). **Превью обязательно + содержание подтверждается.**

### 7. Оплата частями отключена

- **Что:** `installments_payment.id == 1` (выкл) и `monobank_installments_payment.id == 1` у всех товаров
- **Почему:** для среднего чека ≥500 грн рассрочка — стандартный канал конверсии в UA. Без активации товар не показывается в банковских пуллах + на сайте нет опции «оплатить частями».
- **Фикс:** `installments` — установить `installments_payment.id = 2` и `monobank_installments_payment.id = 2`

### 8. Стикер «Распродажа»/«Sale» отсутствует у товаров со скидкой

- **Что:** товары с `price_old > price`, но в `icons[]` нет стикера типа "Распродажа", "Знижка", "Sale"
- **Почему:** стикер — главный визуальный CTA в листинге. Скидка цифровая видна, но стикер ярче и заметнее.
- **Фикс:** `sticker-sale` — добавить стикер из набора магазина (узнать через `icons/export`)

### 9. Inline-стили в `description`

- **Что:** в HTML описания товара десятки `style="..."` (font-size, color, margin)
- **Почему:** не критично для SEO, но захламляет HTML, конфликтует с темой сайта при ребрендинге, не работает в `marketplace_description`. После очистки структура (`<p>`, `<h2>`, `<img>`) сохраняется.
- **Фикс:** `inline-styles` — regex-чистка `style="..."` атрибутов

### 10. Cross-sell не настроен

- **Что:** `accessories[]` пусто, `gifts[]` пусто, `alt_parent[]` пусто у большинства товаров
- **Почему:**
  - `accessories` — блок «з цим товаром купують» → +AOV
  - `alt_parent` — товар в нескольких разделах («Хіти», «Знижки») → внутренняя перелинковка и навигация
  - `gifts` — подарок при покупке → конверсия
- **Фикс:** `cross-sell` — **требует обсуждения стратегии с пользователем** (что и куда привязывать). После этого — пакетный импорт.

## Админка — 8 проверок (через API НЕ исправляются)

### A. Длина title категорий >70 символов

- **Что:** SEO-шаблон выдаёт длинный `<title>` для категорий
- **Почему:** Google режет title в SERP до ~580 px (~65 симв кириллицы). Хвост шаблона (бренд, доставка) теряется.
- **Где править:** **Маркетинг → SEO → SEO шаблони → Категорії** — сократить шаблон до ~50-60 симв.

### B. Пустой description у info-страниц

- **Что:** `<meta name="description">` пуст у /privacypolicy/, /dohliad/, /pro-nas/ и т.п.
- **Почему:** Google генерирует сниппет автоматически (плохо). Заданный description = контроль.
- **Где править:** **Сторінки сайту → Інформаційні сторінки → [страница] → SEO description**

### C. Несколько `<h1>` на странице

- **Что:** на странице больше одного `<h1>`
- **Почему:** размывает семантику для Google. Должен быть ровно один.
- **Где править:** обычно дубль в SEO-тексте → **Сторінки сайту → SEO-текст** (либо в редакторе категории)

### D. Главная без `<h1>`

- **Что:** в `<body>` главной страницы нет `<h1>`
- **Почему:** h1 — главный текстовый сигнал темы страницы. Без него главная теряет вес по бренду + основной категории.
- **Где править:** **Редактор дизайну → Головна → перший блок із заголовком**

### E. Скрытые товары (`display_in_showcase = 0`)

- **Что:** товары не показываются на сайте, но всё ещё в API
- **Почему:** мусор в данных, риск 404 в Google если когда-то были открыты
- **Где править:** **Каталог → Товар →** перевести в архив/удалить или вернуть в продажу

### F. Пустой УКТ ВЕД (`uktzed`)

- **Что:** код товара по украинскому классификатору не указан
- **Почему:** не для SEO. Нужно для ПРРО Checkbox (чек), импорта/экспорта, фидов.
- **Где править:** **Каталог → Товар → УКТ ВЕД** (вручную или CSV-импорт)

### G. SEO-текст категорий — пустой или без структуры

- **Что:** на странице категории нет SEO-текста или есть, но без `<h2>`/`<h3>`
- **Почему:** SEO-текст — основной контент для ранжирования по коммерческим запросам категории. Без структуры — стена параграфов, плохо для Google и читателя.
- **Где править:** **Каталог → Категорія → SEO-текст** — добавить блок 800-2000 симв с h2/h3 («Особливості», «Як обрати», «Догляд», «Доставка»)

### H. h2/h3 в длинных описаниях товаров отсутствуют

- **Что:** description >800 симв без h2/h3
- **Почему:** h2/h3 помогают Google понимать темы внутри текста, и пользователю — сканировать. Особенно для блоков «Особливості», «Догляд», «Розмірна сітка».
- **Где править:** в каждом товаре в редакторе описания заменить `<p style="...">Догляд</p>` на `<h2>Догляд</h2>`. **Можно через API** (фикс `inline-styles` поднимает смысловые подзаголовки до h2/h3 при чистке).

## Баг-проверки данных — 4 проверки (фиксить в источнике)

Эти проверки находят явные баги в данных каталога. Через API их **не фиксим автоматом** — обычно проблема в источнике (Excel/CSV-импорт, ERP, ручная правка). Скилл выводит их в отчёт чтобы клиент знал куда смотреть.

### I. Отрицательная цена (`price_negative`)

- **Что:** товар с `price < 0`
- **Почему:** очевидный баг ввода. Сайт может показывать или ломаться в корзине. Иногда индикатор что в импорте перепутали колонки.
- **Где править:** в карточке товара в админке. Если массово — проверить CSV-импорт.

### J. `price_old < price` (старая цена ниже текущей)

- **Что:** для товара указана `price_old > 0`, но при этом `price > price_old`
- **Почему:** зеркальная ситуация — обычно это значит цены поменяли местами при импорте. На сайте может либо не показывать «зачёркнутую» цену, либо показывать её как «акция» (что вводит покупателя в заблуждение).
- **Где править:** карточка товара / источник данных импорта.

### K. Подозрительно большая скидка (`price_discount_too_high`)

- **Что:** реальная скидка `(price_old - price) / price_old * 100` > 80%
- **Почему:** обычно баг ввода — забытый ноль («99» вместо «9.9»), или неверный десятичный разделитель (запятая/точка), или скидочная цена попала в обычное поле. Иногда — реальная распродажа, надо смотреть.
- **Где править:** проверить вручную, поправить в карточке если баг.

### L. Дубликаты главных изображений между товарами (`dup_main_image`)

- **Что:** два или больше разных товара используют одну и ту же первую картинку
- **Почему:** часто баг при импорте — все товары получают одну и ту же картинку из шаблона. На сайте каталог выглядит сломано, в Google товары не различаются → теряют клики.
- **Где править:** **Каталог → Товар → Зображення** — заменить картинку у дубликатов. Если массово — проверить откуда импортятся пути к картинкам.

## Что НЕ проверяем и НЕ предлагаем

| Не проверяем | Почему |
|---|---|
| `robots.txt` | Стандартный для платформы, доказанно рабочий |
| `sitemap.xml` | Генерируется автоматически, бьётся по 50k URL |
| Schema/microdata | Реализована платформой (Product, Offer, BreadcrumbList и т.д.) |
| Canonical URLs | Настроены платформой |
| Hreflang | Только если у магазина несколько языков (определяется автоматически) |
| URL-формула | Меняется только через поддержку Хорошопа |
| Slug с `/{id}` в конце | Это формат Хорошопа, не баг |
| Внешний CDN/Hosting | Управляется платформой |
| SSL/HTTPS | Платформа делает |

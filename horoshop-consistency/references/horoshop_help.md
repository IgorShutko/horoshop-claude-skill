# Справка Хорошопа — характеристики и атрибуты товара

Выжимка из официальной документации `help.horoshop.ua`, релевантная проверке консистентности.

---

## Где живут поля товара (важно для consistency check)

### Top-level поля (НЕ в `characteristics`)
- `color` — цвет товара
  - Формат на экспорте: `{"id": 5, "value": {"ru": "Золотистый", "ua": "Золотистий"}}`
  - На импорте: строка `"Білий"` или multilang dict
- `brand` — бренд
- `gtin` — штрихкод
- `mpn` — код производителя

### Поля в `characteristics`
Стандартные (документированы):
- `material` — материал
- `weight` — вес
- `consist` — состав
- `country` — страна
- `gender` — пол
- `age` — возраст
- `physics` — физическое развитие (значения через `;`)
- `brain` — умственное развитие
- `social` — социальное развитие

**Кастомные ключи** — у каждого магазина могут быть свои (зависит от шаблона данных). Реальные имена ключей смотри в `catalog/export`.

## Шаблон данных (Шаблон даних)

В Хорошопе **набор полей товара** настраивается в шаблоне:

**Налаштування → Система → Каталог → Шаблон даних**

Здесь админ:
- Включает/выключает стандартные поля (`mpn`, `gtin`, `installments_payment` и т.д.)
- Создаёт **кастомные характеристики** — становятся ключами в `characteristics.<key>`
- Настраивает типы значений: текст, число, выбор из справочника, цвет

Если поле в шаблоне выключено — `catalog/import` вернёт **код 11** при попытке записать. Включи в админке, повтори импорт.

📄 [Создание и настройка шаблонов товаров](https://help.horoshop.ua/ru/articles/3960878-создание-и-настройка-шаблонов-товаров)

## Модификации товаров

### Структура
- **Главный товар** (`article == parent_article`):
  - Имеет общие `description`, `gallery_common`, характеристики
  - На листинге показывается ОДИН раз (не одна карточка на модификацию)
- **Модификация** (`article != parent_article`):
  - `parent_article` указывает на главный
  - Имеет свои `mod_title`, `images`, `price`, `presence`
  - Может иметь свой `gtin`, `mpn`, `color`

### При consistency check
- Проверяй только главные товары (или каждую модификацию отдельно — зависит от задачи)
- `description` обычно общий для всех модификаций — не флагать как «расходится» с цветом конкретной модификации
- `color` у модификации может отличаться от главного товара (это норма для color-вариантов)

📄 [Модификации товаров](https://help.horoshop.ua/ru/articles/4168442-модификации-товаров)

## Цвета товаров

### Точный цвет
- Поле `color` — **что отображается покупателю** (например «Шоколад», «Лаванда»)
- В фильтрах используется группа цветов (для слияния «Шоколад» и «Молочный шоколад» в один фильтр-цвет «Коричневый»)
- Настраивается в **Каталог → Кольори (для фільтрів)**

### Через API
- `color` — строка / multilang
- Если магазин использует точные цвета (которых много) → группа фильтров настраивается отдельно в админке (через API не управляется)

📄 [Характеристики цветов товаров](https://help.horoshop.ua/ru/articles/3961019-характеристики-цветов-товаров-на-сайте)

## Распространённые conflicts (что искать)

### 1. Текст описания vs `characteristics.material`
**Пример:** в `description` написано «100% бавовна», а `characteristics.material` указан «поліестер».

**Причина:** copy-paste при создании похожих товаров — забыли поменять текст / характеристики.

### 2. Текст описания vs `characteristics.country`
**Пример:** «зроблено в Польщі» в описании, `country: Україна` в характеристиках.

### 3. Title vs `color`
**Пример:** заголовок товара «Куртка Чорна», а `color: Білий`.

**Это классический сигнал** что:
- При создании клонировали товар-базу, забыли поменять цвет
- Или в характеристиках всех модификаций одинаковый цвет

### 4. Размеры в title vs description
**Пример:** title: «Комплект 50×70», в `description` размер 70×100.

## Что делать при конфликте

| Конфликт | Решение |
|---|---|
| Текст vs характеристика | Решить руками: что правильно — текст или характеристика. Если описание правильное — обновить `characteristics` через API. Если характеристика правильная — переписать описание. |
| Title vs color | Через `catalog/import` обновить `color` или `title` |
| Размеры в title vs description | Скорее всего описание устарело — обновить через `catalog/import` |
| Системная проблема (много конфликтов одного типа) | Проверить процесс импорта (CSV / XML) — там скорее всего колонки сместились или маппинг неверный |

## Что НЕ ловит regex-проверка

- Семантические соответствия (синонимы, перифразы): «велюр» ≈ «фланель» — нет
- Пограничные случаи («микросатин» vs «сатин» — это конфликт или нет?)
- Контекст (если в описании сказано «изначально из хлопка, теперь из полиэстера» — regex выдаст false positive)
- Многоязычные кросс-сравнения (если в ua-описании одно, в ru — другое)

Поэтому скилл выдаёт **низкий recall, высокую точность** — лучше пропустит редкий случай, чем выдаст ложный конфликт.
